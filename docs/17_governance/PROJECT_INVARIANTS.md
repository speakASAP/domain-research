# Project invariants

completeness_level: complete

status: validated

## Purpose
This document defines the invariants for the Domain Research service and keeps the repo aligned with its real responsibility boundaries and evidence-driven workflow.

## Applicability
These invariants apply to this repo’s operational flow, status artifacts, and runtime responsibilities.

## Invariants
- Domain Research must remain truthful about its ownership boundary and not claim auth, payment, or purchase infrastructure ownership.
- Availability checks must remain evidence-backed and based on the approved provider model.
- Notification delivery must remain tied to the approved notifications contract and recipient policy.
- Adoption and validation artifacts must remain traceable and consistent with the service’s actual scope.

## Exceptions
Any exception must be documented with a clear reason and the owner-approved operational review evidence that supports the change.

## Review cadence
Review this file whenever the service’s provider strategy, notification boundary, or watch workflow changes.
